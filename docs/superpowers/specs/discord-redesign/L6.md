## 1. Elements

### 1.0 Board-wide rules

- L6-01 · The whole application is one form in three consecutive windows: games, about you, game accounts, clan questions; the thread is created only after the final submit.
- L6-02 · Windows use select menus for games, category, "odkud o nás ví", specialization, "kdy hraje" and "kdo ho pozval".
- L6-03 · Between windows one private message shows the summary, "Upravit" per completed step and "Pokračovat".
- L6-04 · Recruiters decide with buttons on the thread card; `/close_application` stays as a backup. Private messages end with "Tuto zprávu vidíte jen vy · Zavřít zprávu"; windows have a close (×) button "Zavřít".

### 1.1 Průběh a pravidla oken

- L6-05 · Flow: panel `#nabor` "Podat přihlášku" → Okno 1 "O tobě" → message "Pokračovat" → Okno 2 "Herní účty" → message "Pokračovat" → Okno 3 (3b) "Otázky klanu" → message "Kontrola" → "Odeslat" → thread created.
- L6-06 · A window holds at most 5 fields; more clan questions open window 3b, then 3c.
- L6-07 · A window cannot open another window; between windows one private message is edited in place and its "Pokračovat" opens the next window.
- L6-08 · Answers are saved after every window; an unfinished application is kept 24 h, then deleted; the thread exists only after "Odeslat přihlášku".
- L6-09 · "Upravit" reopens that window with the saved values prefilled.
- L6-10 · Field "Hry" is hidden when the clan recruits for one game; window "Otázky klanu" is hidden when the category has no questions; "Specializace" is only for Hell Let Loose.
- L6-11 · Limits: window title and field label ≤45 characters, field description ≤100 characters, a select ≤25 options; window buttons are always "Zrušit" and "Odeslat" (not customisable).

## 2. Behaviour and data

- L6-B01 · Windows hold ≤5 fields; overflow questions spill into 3b/3c; window order is fixed (O tobě, Herní účty, Otázky klanu).
- L6-B02 · The interstitial is one ephemeral message edited in place; only its "Pokračovat" opens the next window.
- L6-B03 · Draft saved server-side after each window; TTL 24 h; expired windows keep saved steps.
- L6-B04 · Thread and card are created only on final submit; recruiters never see drafts.
- L6-B05 · Steam verified on the web is detected and the interstitial updates itself; the window prefills it.
- L6-B06 · Previous-player lookup uses the in-game name from window 1 against the clan's servers.
- L6-B07 · Steam field accepts a 17-digit ID starting 7656119 or a profile URL; validated on submit.
- L6-B08 · Decision buttons: fresh permission check (category support or Logi admin); accept writes membership, queues roles, sends the DM, locks and archives the thread; "Ještě nerozhodnuto" only records who/when.
- L6-B09 · `/close_application` remains with the same outcomes and permission check.
- L6-B10 · The web form (Varianta B) is behind a switch, off by default, and produces the same thread and card.
- L6-B11 · Discord limits (45/100/25 characters/options, 5 fields) are enforced when admins build the form (N4).
- L6-B12 · Field "Hry" hidden for single-game clans; "Specializace" only for HLL; question window hidden if the category has none.

## 3. Owner decisions applied

- **Application defaults to the Discord windows.** **Varianta B (web form) is "varianta, nevybráno" as default**: it exists behind a switch that is off by default (N4).
- Decision buttons on the card: accept as člen, rekrut or žoldák, or reject with a reason (DECISIONS). **Resolved by the spec `docs/superpowers/specs/2026-10-05-discord-redesign-design.md`:** the card has all five buttons — "Přijmout jako člena", "… rekruta", "… žoldáka", "Zamítnout…" (with a reason) and "Ještě nerozhodnuto"; `/close_application` keeps working. N4's three-button preview/table must be extended accordingly.
- One form in several windows, submitted at the end; thread created only after submit.
