## 1. Elements

### 1.0 Board-wide rules

- L5-01 · System messages (errors channel, service status, status thread) have a neutral grey bar so they never look like clan messages; DMs (team requests) keep the clan colour.
- L5-02 · Written in the clan language without internal names: what failed, what it concerns, what to do.
- L5-03 · Errors channel: a Czech sentence and a fix step replace "Bot action failed · Discord said · Scope".
- L5-04 · Service status in Czech, each service state as a chip, changes posted in the thread "Změny stavu".
- L5-05 · Team requests as V2 cards with the clan colour; the result is a chip.

## 2. Behaviour and data

- L5-B01 · System cards use the grey bar `#80848E`; DMs use the clan accent.
- L5-B02 · Every Discord failure is mapped to a localized "Proč"/"Co udělat" pair by error class (missing permission, missing access, unknown channel, role hierarchy/missing role, full category/server, timeout, other).
- L5-B03 · Each entry states its retry mode with a chip: "Zkusí se znovu po opravě", "Zkusí se znovu sám", "Hráč dostal zprávu, ať to zkusí později".
- L5-B04 · No raw `error.message`, codes, internal scopes/steps or record IDs are posted.
- L5-B05 · Member lists in an entry are capped at 5 names.
- L5-B06 · Service status checked every 30 s; one message edited; one thread message per change, recovery message carries the outage duration.
- L5-B07 · Game servers are excluded from service status.
- L5-B08 · Player-facing replies for admin-fixable errors are one short sentence ("správci dostali upozornění").
- L5-B09 · Late/absence post in the match thread is optional, off by default, and never shows the reason.

## 3. Owner decisions applied

- **Late or absent notices**: optional post in the match thread, **off by default**, never showing the reason (L5-43, toggled in N1).
- Clan language everywhere; system messages for admins use the grey bar (brief).
