## Reported deviation checked: "option names stay in English"

Not accurate as a user-visible statement. `discord-bot/src/commands/definitions.ts:40-62` keeps the English key as the option's default `name` (what handlers read with `getString("game")`), but sets `name_localizations` for **all 32 Discord locales** to the clan-language name. The dump shows `nameLoc(32 locales)=["hra"]`, `["období"]`, `["člen"]`, `["výsledek"]`, `["důvod"]`, … for cs and `["spiel"]`, `["zeitraum"]`, `["ergebnis"]`, … for de. Every Discord client therefore shows `hra`, `období`, `kanál` exactly as M1 1.4 draws them. All localized names pass Discord's name regex and lower-case rule (checked in the dump script).

Is English forced by Discord? No. Discord accepts lower-case Unicode names such as `období` as the default `name`. Keeping an English key is an implementation choice, so handlers do not need language-aware option lookups. The only visible trace is the interaction payload, which is internal. A future Discord locale added after discord.js's `Locale` enum would fall back to the English key. Verdict: the visible result matches the board. The internal mechanism differs from M1-B02's wording; see M1-B02.
