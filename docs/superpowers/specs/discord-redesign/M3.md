## 1. Elements

### 1.0 Board-wide rules

- M3-01 · For each command: success, "nepovoleno" (not allowed), "jinde" (wrong place) and the form when it opens one; all errors in one style.
- M3-02 · Replies in the clan language, including `/server-status` (today it follows the Discord language).
- M3-03 · No English fallback sentences ("this server", "Use this command inside a ticket thread").
- M3-04 · `/close_ticket` and `/close_application` verify roles the same way and freshly.

### 1.1 Jeden styl chyb

- M3-05 · Anatomy: the reason as the title, one short sentence ("Tento ticket můžou zavřít jen podpora a správci."); below it what to do now and where; at most one button when it really helps (link, "Zadat znovu", "Vybrat jiný kanál").
- M3-06 · Always private (Discord shows the header "<jméno> použil(a) /<příkaz>" above and "Tuto zprávu vidíte jen vy · Zavřít zprávu" below), in a clan-colour container (no red bar), in the clan language; no codes, IDs, English words or developer sentences.
- M3-07 · When an admin must fix it, the error also goes to the errors channel (L5) and the person gets only "správci dostali upozornění"; "nepovoleno" says who may; "jinde" says where it works.

## 2. Behaviour and data

- M3-B01 · Every command and button error uses the shared error card (title + next step + ≤1 button), ephemeral, clan language.
- M3-B02 · Admin-fixable errors are also posted to the errors channel (L5).
- M3-B03 · `/notice` lists and accepts only the caller's signed-up, not-started events; a saved notice stops attendance reminders for that match; a later `/notice` replaces it.
- M3-B04 · `/server-status`: Logi admins only (Administrator or admin role), fresh check; at most 5 servers; stored data with freshness and provider; clan language.
- M3-B05 · `/close_ticket` and `/close_application`: same fresh check (guild, roles, member); category support or Logi admins; only in the matching thread type.
- M3-B06 · Close commands report whether the DM was delivered.
- M3-B07 · `/close_application` outcome writes membership and queues roles; reply states which roles will be added.
- M3-B08 · `/link` IDs validated per platform (Steam64: 17 digits starting 7656119).

## 3. Owner decisions applied

- Clan language for all replies; staff commands visible to all, permission checked when used.
- `/link` verification and other platforms are **not decided** (brainstorm postponed); M3-09..13 describe the board.
- Decision buttons (L6) are the main application path; `/close_application` remains as backup with the same outcomes.
