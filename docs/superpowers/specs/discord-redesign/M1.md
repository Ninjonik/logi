## 1. Elements

### 1.0 Board-wide rules

- M1-01 · The board defines what appears after typing "/", who may use each command, where the reply lands, and descriptions in Czech, English and German.
- M1-02 · New `/help`; `/player` replies privately with "Sdílet", like `/stats`.
- M1-03 · One permission model for all commands, checked freshly from Discord.
- M1-04 · Descriptions in the clan language for the whole server; commands are also registered when the bot is added to a server.

### 1.1 Jak příkazy vypadají v Discordu

- M1-05 · Command names are English and identical in every language; options and descriptions are in the clan language.
- M1-06 · The "/" menu is the same for everyone (Discord cannot hide a command by a Logi role); `/help` shows only what the person may use.
- M1-07 · Menu row "/close_application" with option hint "výsledek" and description "Rozhodne o přihlášce v tomto vlákně a uzavře ji", app "Logi".

- M1-11 · Menu row "/notice" with option "akce" — "Dej velení vědět, že na akci přijdeš později".
- M1-12 · Menu row "/player" with option "hráč" — "Profil hráče klanu: skóre a poslední zápasy".
- M1-13 · Menu row "/server-status" with option "hra" — "Uložený stav herních serverů klanu (pro správce)".

- M1-17 · Registration at bot start for every server the bot is in.
- M1-18 · Registration immediately when the bot is added to a new server (today only after a restart).
- M1-19 · Re-registration after the clan language changes, so descriptions and options use the new language.
- M1-20 · Descriptions and options are registered in the clan language for the whole server, without per-user Discord-locale translations; commands work only in a server and are not offered in DMs.

### 1.2 Kdo smí co

- M1-21 · Three groups, identical for all commands; Logi checks permission on every use directly from Discord, not from cache.
- M1-22 · "Všichni na serveru": every member of the Discord server; Logi still guards content: `/stats` only enabled games, `/notice` only own events, `/link` only own accounts.
- M1-23 · "Podpora kategorie": roles from Tickety → kategorie → "Kdo odpovídá" and Členství → kategorie → "Kdo žádosti vyřizuje"; valid only in threads of their category.
- M1-24 · "Správci Logi": Discord Administrator permission or the admin role from Nastavení → Role a přístup; the same group as on the web.
- M1-25 · Unification: `/server-status` is allowed to Správci Logi (not only Manage Server) and read freshly; `/close_application` verifies like `/close_ticket` (fresh guild roles, not only the member); `/player` stops replying publicly.

## 2. Behaviour and data

- M1-B01 · Commands are (re)registered on ClientReady for every guild, on GuildCreate, after a clan-language change and after saving command settings (N3).
- M1-B02 · Names stay English; descriptions, option names, option descriptions and choice names are registered in the clan language as the default, with no per-locale localizations.
- M1-B03 · Commands are guild-only (no DM context).
- M1-B04 · The three permission groups are resolved freshly from Discord on each use.
- M1-B05 · `/help` lists only commands the caller may use.
- M1-B06 · `/player` reply is ephemeral with "Sdílet".
- M1-B07 · `/server-status` is allowed to Administrator or the Logi admin role, checked freshly.
- M1-B08 · `/close_ticket` and `/close_application` use one fresh check (guild, roles, member) and category support roles.
- M1-B09 · `/server-status` lists at most 5 servers.
- M1-B10 · `/notice` autocomplete lists only own signed-up, not-started events, labelled in the clan time zone.
- M1-B11 · Reason options are capped at 500 characters.

## 3. Owner decisions applied

- `/player` replies privately with a "Sdílet" button.
- New `/help` command.
- Staff commands are visible to everyone in Discord; permission is checked when used.
- All command replies and descriptions use the clan language.
