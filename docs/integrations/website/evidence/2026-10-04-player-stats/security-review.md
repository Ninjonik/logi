## Threat Model

Logi combines a Next.js dashboard/API, Convex persistence and a Discord.js gateway. At HEAD 8b07862a077a6d25a4005e69dbc8ca9bdeaa88f6, /stats reads guild-scoped retained Wardogs history or fixed-host public HLL profiles, returns an ephemeral card, optionally updates the caller's legacy Steam lookup key, and explicitly publishes a refreshed snapshot to an authorized Discord channel. Bot-only and combined development scripts execute the same source entrypoint (package.json:12-13; discord-bot/src/interactions/stats-live.ts:14-54).

### Assets

- Exact Discord user bindings, self-declared users.platformIds, and separate verified platformIdentityLinks authority (convex/discordPlayerStats.ts:43-135; convex/platformIdentityLinks.ts:121-178).
- Guild-isolated retained game facts, Steam identities, source identifiers and revision-consistent aggregate integrity (convex/gameHistoryStore.ts:31-120; convex/discordPlayerStats.ts:140-217).
- INTERNAL_AUTH_SECRET gateway authority, Discord bot token, dashboard sessions and authorized message-publication capability (discord-bot/src/environment.ts:13-36; convex/dashboardSessionStore.ts:8-49; discord-bot/src/interactions/stats-publish.ts:9-31).
- Shared runtime availability: bounded provider requests, history scans, caches, private interaction state and local artwork reads (discord-bot/src/interactions/stats-runtime.ts:134-240; src/infrastructure/hll-records/read-profile.ts:81-243; discord-bot/src/public-panels/assets.ts:10-45).

### Trust Boundaries

- Discord supplies interaction actor and guild identity. Stateful controls bind random 64-bit IDs to the original requester/guild, expire after 15 minutes, reserve busy synchronously, and clear on restart. Initial results are ephemeral (discord-bot/src/interactions/stats.ts:277-306,369-407).
- Bot-to-Convex is a privileged gateway, not independently verified end-user authentication. The bot force-fetches requester and selected member membership; Convex checks the shared secret, snowflake syntax, observation age and configured guild. It trusts the gateway's claimed actor and membership evidence (discord-bot/src/interactions/stats-live.ts:18-45; discord-bot/src/interactions/stats-runtime.ts:61-88; convex/discordPlayerStats.ts:25-49).
- Self-link writes address exact users.discordId only, reject imported-ID collisions, compare expected prior IDs and check both verified and legacy duplicate claims. They patch only legacy platformIds or create an unprivileged user; verified OpenID completion writes a different table after its own challenge/replay checks (convex/discordPlayerStats.ts:64-135; convex/platformIdentityLinks.ts:121-178).
- Wardogs reads cross the guild data boundary through indexed guild filters. Selected-player reads filter player facts; autocomplete deliberately reads all retained players in that guild. ### Attacker Capabilities

- An ordinary member of a configured guild can invoke stats, choose another current member, choose a retained Wardogs Steam/source ID, submit an unverified Steam key for their own account, and attempt sharing where their current channel permissions allow it.
- The caller does not initially possess INTERNAL_AUTH_SECRET, the bot token, another user's Discord identity, verified Steam ownership, operator source configuration or local filesystem write access. Those authorities must not be assumed to manufacture an exploit.
- Provider-controlled names, HTML and recorded map/faction/server labels are untrusted display data. They do not gain script execution or arbitrary fetch/file-path authority through the inspected adapters; displayed text is escaped and mentions neutralized (discord-bot/src/interactions/stats-render.ts:10-13,83-96,124-134,170).
- A failed boundary could expose another guild's facts, overwrite another subject's lookup identity, publish with bot-only permissions, or consume shared resources. Architecture mapping alone does not establish any such failure.

### Security Objectives

- Preserve exact Discord-subject and guild isolation, including fresh membership checks before and after reads and before linking/sharing (src/application/game-data/read-player-stats.ts:40-72; discord-bot/src/interactions/stats-runtime.ts:105-132).
- Keep self-declared lookup keys distinct from verified ownership, membership, role or SSO grants; reject collisions and stale concurrent forms.
- Require explicit publication with current requester and bot permissions, suppress mentions, and prevent concurrent or replayed controls from duplicating one state's share attempt.
- Keep provider destinations and artwork paths constrained; enforce bounded requests, scans and caches; preserve original timestamps and stale labels after provider failures.
- User-provided context: perform this review offline and read-only, do not read credentials, bypass the HLL 403 provider gate or deploy production.

### Assumptions

- This is a source-backed architecture pass, not completed vulnerability-audit coverage. HEAD and clean worktree were verified; cited source paths and line anchors were checked. No app/tests, external services or credential files were accessed.
- User-provided context says prior runtime work used isolated loopback Convex and an authorized test guild. Those deployment claims were not independently revalidated here. Production and unattended successful HLL access remain separate acceptance gates (docs/integrations/website/discord-player-stats.md:95-122).
- Actual configured Convex URLs, secrets, filesystem deployment layout and replica count are unknown because runtime/credential inspection is excluded. Bot scripts use source execution; the tracked self-hosted Convex compose is a distinct supported configuration, not proof of the tested deployment.
- Source-comment discrepancy: convex/discordPlayerStats.ts:25 says membership must be freshly fetched before each call, while discord-bot/src/interactions/stats-runtime.ts:81-88 intentionally reuses evidence younger than five seconds; Convex accepts up to ten seconds at lines 28-35. The enforceable architecture is bounded-age gateway evidence plus pre/post-read reauthorization.
- Publication refreshes data immediately before sharing; it is not cryptographically bound to the earlier preview's exact bytes. Deduplication is process-local state, with old controls failing after restart (discord-bot/src/interactions/stats.ts:286-306,318-326).
- Parent qualification: the seven-second HLL limit bounds asynchronous transport, not a separately isolated synchronous parser CPU budget. HTML input remains capped at two MiB. Production network/storage exposure was not inspected.
