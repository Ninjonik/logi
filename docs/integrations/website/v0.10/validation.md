## Evidence and limits

Before final review, the full suite reports **508 tests: 507 pass, one unchanged
baseline failure**. Typecheck passes, including the refreshed Convex type inventory.
Direct ESLint on D4's changed TypeScript reports **zero errors and six existing
warnings** (four unused exclusions in `publicApi.ts`, one event-page metadata
import, one OpenAPI helper). The final independent review and any subsequent
regression checks are recorded in [review](review.md).

- The unchanged `discord-bot/src/message-builders.test.ts:434` assertion expects
  `Alpha\nDelta\nGolf`, while the existing implementation returns
  `Alpha\nEcho\nCharlie`. It is the known upstream embed-column ordering failure.
- The existing `npm run lint` invokes unsupported `next lint`; use direct ESLint
  on changed source. Whole-branch checks additionally include the known three
  `no-explicit-any` errors in `convex/competitions.ts:52,54,58`.
- Production compilation and TypeScript succeed. Prerender of `/cs/competitions`
  fails with `ECONNREFUSED 127.0.0.1:32199` because the synthetic Convex endpoint
  deliberately has no server. This is **not** a successful full build.
- OpenAPI is generated by `npm run generate:openapi`; generated source is not
  edited by hand. Runtime read DTOs come from closed domain schemas.
- `node scripts/generate-convex-api-offline.mjs` invokes the installed official
  Convex API template for the current top-level modules, preserving the empty
  component declaration. This refreshes type inventory only, contacts no backend
  and does not replace deployment-aware target codegen.
- Isolated Convex test handlers exercise append/CAS, rollback and replay behavior
  with an in-memory transactional fixture. They do not simulate real multi-process
  contention, hosted limits or deployment authorization.
- Browser proof uses the real component/styles and actual handler/use-case wiring,
  with synthetic account authority and storage. See [UI proof](ui-validation.md).
  No browser automation performed a real Steam sign-in or Discord operation.

The full suite must run with the synthetic bot variables; omitted environment
is a test setup failure, not feature evidence. A passing focused test is not a
substitute for deployment or website acceptance.
