# Dashboard/API parity: implementation work register

Date: 2026-11-11. Read with the [master plan](../maintenance-implementation-plan.md), existing [configuration reference](../integrations/website/configuration-coverage.md) and actual route/Convex inventories. This is an operation-family assessment, not a claim that every field of every contract is already equivalent. HTTP route counts are not operation counts: the catch-all, settings slices and personal league command each dispatch many operations.

## Authority model to preserve

Distinguish public reads, clan service-key operations, clan operations requiring an SSO user actor, personal first-party sessions, platform administrators and trusted bot work. The fact that an operation appears under `/api/v1` does not mean a clan key may perform it. `/me/leagues` already exists and deliberately uses a personal session. Do not add a service-key impersonation path to close a parity spreadsheet.

For all supported equivalents, compare input semantics, validation, resource ownership, game, actor freshness, dependent writes, revision conflict, replay, publication, redaction and cache effects. Sharing a use-case name is insufficient (A24 demonstrates that adapters can still change transaction behavior).

## Required deliverables during implementation

Produce the executable operation manifest described in M03 with one row per actual operation/variant, not one row per family above. Seed it from all **151 route files**, the server-action module, direct client Convex calls, all **582 mechanically discovered registered Convex exports**, bot feature registrations and settings slices. Check delegated/dynamic operations manually; these counts are discovery anchors, not a complete semantic operation count.

Every row must end as supported with contract tests, or an explicit justified exception with authority/risk rationale and reconsideration condition. `Gap`, `unknown`, and `decision pending` block parity completion. Previously documented exclusions must be retained or deliberately replaced; they cannot be silently reclassified as implemented. API read models may differ from dashboard aggregates; shared business invariants must agree.

For a new write operation, deliver its schema, grant/actor requirements, shared command/repository wiring, revision and replay behavior, error/status contract, OpenAPI, technical reference, wiki, cache effects and adapter regression tests in the same change. Preserve established v1 paths and envelopes while consolidating internals.
