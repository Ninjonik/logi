# Reporting bugs

Select **Report a bug** at the bottom of the dashboard sidebar. Enter a short title and describe what happened, what you expected, and how to reproduce the issue.

Optionally select a server or type its name or ID. This is context for the report and does not grant access to that server. When opened from a workspace, its server is filled in for you. You can also specify the incident time in your local time zone; leave it blank if you are unsure. The incident time cannot be in the future. Invalid or future incident times show a specific error so you can correct the value or clear the field.

Attach screenshots or logs using the file picker. You can add or remove files before sending. Supported formats are PNG, JPEG, WebP, GIF, TXT, LOG, JSON, CSV, and ZIP. Each report accepts up to five files of 5 MiB each. Remove passwords, tokens, and other sensitive information before uploading.

After sending, a confirmation appears. Signed-in users can send up to ten reports per hour. If sending fails, your text and selected files remain available to retry.

## Superadmin review

Logi superadmins can open **Bug reports** under global administration. The inbox lists the newest reports first and includes the reporting Discord account ID, submission time, optional server and incident time, and attachment downloads. Use **Load more** to view older reports. Change the status to **New**, **Investigating**, or **Resolved** to track progress. Reports and downloads are available only to superadmins.

## Optional GitHub connection

Operators can install a GitHub App on their repository to connect reports using the [GitHub setup guide](https://github.com/Ninjonik/logi/blob/main/docs/github-issues.md). When enabled, new reports create issues automatically, normally within a minute. Report text and server context are copied to the repository; do not include secrets. Attachments and reporter account IDs remain in Logi.

The superadmin inbox shows the GitHub issue link, imported comments, and delivery errors. Changing a report to Resolved closes its issue; New or Investigating opens it. Status changes also add a GitHub comment. Closing the issue in GitHub resolves the report, and reopening it changes a resolved report to New. Reload the inbox to see updates. GitHub comments are displayed for review; the inbox does not offer a comment editor.
