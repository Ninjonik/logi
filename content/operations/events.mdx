# Events

Events are the central schedule for a server. They can represent a general community event, a match, or another planned activity. Managers create and edit events; members use them to understand timing and respond when sign-up is enabled.

Saving, importing, concluding and submitting results for an event in the
dashboard require current workspace administrator access. If your session has
expired or your administrator access was removed, Logi shows a message asking
you to sign in again instead of saving.

## Connected clan websites

A configured clan website can create and update the same native Logi event.
Changes made in Logi or Discord are then available to the website through its
event synchronization. Website publication remains a separate editorial choice.

Website event editing requires a current Logi sign-in and an explicitly allowed
Discord role for the selected game. Signing in alone does not grant access. If
membership cannot be verified or another editor changed the event, the website
must refresh the information before accepting a new edit.

The website command supports match or training names, descriptions, maps, sides
and schedule times. Updates and cancellation are available before meeting start.
For matches, the website can also select active workspace teams for each slot
with an optional side or faction, and explicitly refresh one selected team's
saved name, short code and logo from the team directory. That refresh stays
available after meeting start until the match concludes. Logi records each
team's presentation when it is selected; an edit that leaves teams out keeps
the current selection, and a concluded match keeps its teams unchanged.
Trainings never carry team selections.
Cancelling records an early conclusion through a separate cancellation action and awards no attendance
points. Discord settings, rosters and result confirmation remain managed in
their dedicated Logi workflows. An event created from a website does not enable
clan pings or forum creation automatically.

Operators can use the [website event command contract](https://github.com/Ninjonik/logi/blob/main/docs/integrations/website/event-commands.md)
to configure a dedicated application/key policy and per-game role allowlist.

## Create an event (manager)

<Steps>

### Start a new event

Open the workspace **Events** page and choose **Create event**. If you started
from **All games**, first select the intended game in the game-selection panel.
Enter a descriptive name before adding optional details.

### Set the schedule

Add the meeting time and, where needed, the game start/end time. These are distinct: meeting time is when people gather; game time is when the activity is expected to run. Optionally set **Registration announcement start** to delay Discord registration messages and match forum posts; the event remains visible in Logi and Discord calendars until that time. Leave it empty to publish immediately.

### Add operational details

Choose available map, side, mode, capacity, topic preset, stratmaps, and
Discord-related options only when they apply to the event. Maps, caps,
stratmaps, groups, and eligible membership assignments are limited to the
event's game. A membership for one game does not make a player eligible for a
different game's members-only event.

### Save and verify

After saving, reopen the event and confirm the time, timezone, sign-up settings, and visibility are correct before telling people about it.

</Steps>

### The exact sign-up rules

Sign-up is available only while the event is in **registration**. For a
training, registration remains available after it has moved to **starting** if
the registration deadline has not yet passed. Match sign-ups are more
restricted: the person must have a non-pending membership status. By default,
recruits, members, reserve members, and mercenaries may sign up, unless the
manager narrows the event's allowed membership statuses.

An event can also require one or more Discord roles. Holding _any one_ of its
required roles is enough. A group-specific match choice is available only when
the group is visible on the event and the person either holds that group’s
linked Discord role or has the group assigned in Logi. The optional **general
signup** avoids choosing a group; when the member has a primary group that is
visible on the event, Logi records that primary group instead.

Selecting **not attending** records a decline; it does not erase the person's
participation record. A later response replaces the old one. A sign-up says
someone is available—it does not place them into a squad or confirm that they
attended.

## Event timeline and automation

| Status       | When it applies                                                                                                        | What changes for members                                                                                                               |
| ------------ | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Registration | Before the registration deadline                                                                                       | Eligible people can sign up.                                                                                                           |
| Closed       | After registration closes, before the event is starting                                                                | New sign-ups are blocked.                                                                                                              |
| Starting     | From the later of the registration deadline and 24 hours before the meeting time, until the duration plus reserve ends | Sign-ups are normally blocked; training retains the exception above. Published-roster attendance acknowledgement is available.         |
| Concluded    | When a manager concludes it after the meeting has started, or 15 minutes after the planned duration ends               | Discord event messages are removed, temporary event roles and squad voice channels are cleaned up, and event scoring is resolved once. |

The dashboard/bot background work reconciles time-based statuses; it is not a
promise that every visual update happens at the exact second. Editing an event
also recalculates its status. Moving an unconcluded event's registration
deadline back into the future can return it to **Registration**. If its old
Discord scheduled event cannot be scheduled again because Discord considers it
active, completed, or cancelled, Logi discards that Discord event and creates a
new scheduled event instead.

### Discord behavior per event

Match signup names are sorted within each group using the server's configured
Discord language, independently of the bot host's language. Legacy embeds read
left to right across each row; compact Components V2 messages keep that same
order. Czech sorting treats **Ch** as a letter after **H**.

Discord output needs the bot running and the relevant server or event-level
channel configuration. The event's announcement and event-info channels are
chosen when the event is created and are kept for later edits; changing those
fields in the editor does not move existing Discord messages to a new channel.
For matches, a forum post is enabled by default unless disabled; trainings do
not create forum posts. When a forum channel exists, the registration and
event-information embeds link directly to that event's forum channel. A
scheduled Discord event exists only when the selected meeting channel is a
voice or stage channel. If that channel is removed or is not a supported type,
Logi cancels its linked scheduled event.
An optional registration announcement start delays Discord registration messages,
event announcements, and match forum posts, without delaying calendar entries or
Discord scheduled events. Events created before this option was added have no
start time and continue to announce immediately.

Events have a planned duration (90 minutes by default, including legacy
events) and a 15-minute reserve before automatic conclusion. Managers may
conclude an event at any time after its meeting start. An event can also create
one temporary voice channel for each non-empty roster squad at meeting start.
Enable this per event and select a category there, or leave the category empty
to use the server's default squad-voice category. Those channels are removed
when the event concludes.

The bot creates temporary Attendees and Reserves roles for non-concluded
events. Attending sign-ups and squad placements feed Attendees; roster reserves
feed Reserves and are excluded from Attendees. Both are deleted at conclusion.

### Absence notices and reminders

An attendee or roster reserve may submit one absence notice per event before
game start; saving another replaces their previous notice. People not attending
and people who are neither an attendee nor a reserve cannot submit one.

For a **published** roster in **starting** status, the bot can direct-message
unacknowledged squad players and reserves at 24, 18, 12, and 6 hours before the
meeting time. Direct messages are skipped when unavailable, and each successful
offset is logged so it is not sent twice. The message's acknowledge button only
marks the person as acknowledged; a manager must mark them confirmed when that
is appropriate.

### Daily match signup reminders

For matches, managers can choose which membership categories receive a direct
message reminder to sign up. The default is active regular members only;
recruits and reserve members can be added, while mercenaries are never included.
The bot sends a compact registration summary and controls 24 hours after
creation, then every 24 hours while registration remains open. It does not
show the signup list because that list is only live in the event registration
message; when available, the DM links to the registration channel and event
forum. Its controls let the recipient sign up, change their signup, or decline
directly from the DM. Clear every recipient category to turn the reminders off
for that match. A member stops
receiving these reminders as soon as they choose either attending or not
attending. Memberships without a game assignment are treated as Hell Let Loose
members for Hell Let Loose matches. Matches that were created before this setting was added use the
regular-member default as well, so members who had already responded are still
excluded from their first reminder.

## If saving is denied

Creating or editing an event (including a Wardogs match registration), importing
results and concluding events require a current workspace administrator session.
If a save reports that only administrators can change the event, sign in again
and check your access to that workspace. If an administrator still cannot save,
ask the Logi operator to check that `SITE_URL` matches the public dashboard URL.
This also applies when Logi runs behind a reverse proxy: its internal container
address is not the browser's origin. API keys do not replace an administrator
session for these dashboard actions.

## Event status and conclusion

Managers can conclude an event when it is finished and record relevant results.
At conclusion, Logi applies the configured event-score rules once. A match that
was concluded before its meeting time is treated as cancelled for scoring.

<Callout type="warning">
    Changing core scheduling or capacity information after people have signed up
    can confuse attendees. Check the event’s connected roster and Discord
    communication before making late changes.
</Callout>
