## Team catalogue and team requests

Logi keeps one global team catalogue per game (Hell Let Loose and Wardogs). Only
global administrators (superadmins) manage it, from **Team catalogue** and
**Team requests** in the superadmin navigation group. Workspaces only read the
catalogue: their administrators pick catalogue teams for matches and send a
request when a team is missing or out of date.

On **Team catalogue**, choose the game tab, search by name or short code and
switch on **Show archived and merged teams** to see retired entries. Each team
has a name (unique per game, ignoring letter case and extra spaces), an optional
short code, logo, description (up to 500 characters) and up to three https
links. A team can be linked to one Logi workspace to record that the team is
that workspace's clan; the link grants no permissions. Logos uploaded here are
normalized to a 512×512 PNG and belong to the platform, not to a workspace.

- **Archive** hides a team from new selection and from connected websites;
  saved matches keep their snapshot. **Restore** brings it back unless another
  active team has taken the name meanwhile.
- **Merge** retires a duplicate into the team that stays (an active team of the
  same game). The duplicate is archived with a pointer to the kept team, and its
  competition registrations, fixtures and pending requests move to the kept
  team. Saved match snapshots are not rewritten. A merge cannot be undone.
- Every save, archive, restore and merge is checked against the version you
  loaded. If someone else changed the team first, the dialog or row shows the
  latest version and keeps your own edits; review it and try again.

On **Team requests**, pending requests are listed oldest first; the status
filter also shows approved, merged, rejected and cancelled requests. Each
request shows the requesting workspace, the requester's Discord ID, whether it
is a new team or a change request, the game, the proposed fields with the logo,
the requester's note and, for a change request, the team as it is now with the
changed fields marked.

- **Approve** opens an editable copy of the proposal. Approving a new-team
  request creates the team; approving a change request applies the fields to
  the current team at the version shown, so a team that changed meanwhile has to
  be reviewed again. The requester's logo becomes a platform logo. If an active
  team of the same game already uses the name, you are offered to merge the
  new-team request into that team instead.
- **Merge into existing team** (new-team requests only) records that the
  requested team already exists: choose an active team of the same game.
- **Reject** requires a reason of up to 500 characters.

Every decision sends the requester one Discord direct message in the requesting
workspace's language with the outcome, the requested name, the resulting team
or the rejection reason. The bot retries a failed message a few times with
increasing delays; when the requester's DMs stay closed the request shows
**Could not be delivered**, and the decision itself stands. Requests a workspace
withdraws are shown as cancelled and send no message.

## Bot dashboard and logs

Logs document what the bot attempted or observed; they are not a guarantee that
Discord completed a requested change. When diagnosing an issue, compare the log
entry with the affected Discord channel/role and the saved dashboard setting.
The error channel is optional, so a missing Discord error report does not prove
that the bot had no error.

The bot dashboard provides operational visibility into bot activity, including timestamp, level, source, scope, message, and context. Use it to investigate a specific issue, not as a place to expose private data. Copy only the minimum useful diagnostic information into a support report.

It is a superadmin-only page, separate from normal server-manager access. It
reads the application's local system-log database and can filter by free-text
search, level (INFO/WARN/ERROR), source (Next.js or Discord bot), and known
scope. A blank or quiet log table is not a live bot-health check, and an entry
records an application-side attempt or observation rather than a guarantee that
Discord completed the operation.

## Competitions

Competition changes can affect public standings immediately. Linking an event
to a fixture creates or updates the association; saving a match result can mark
that linked fixture final and copy its two scores. This is not a replacement for
checking the official competition result, opponent, division, or forfeit rules.

Merging competition clan aliases is especially high impact: it transfers
competition-team and fixture relationships to the selected primary clan and can
delete duplicates. Confirm both clans and all current fixtures before doing it.

The dashboard competition area is distinct from the public competition pages. Elevated users may manage platform-side competition information; always verify the selected workspace and source data before modifying fixtures or links.

## LogiComms

Access to elevated pages is separate from ordinary workspace manager access.
If an elevated page or action is absent, do not assume a normal Discord role is
enough; verify the account's platform-level authorisation. Conversely, elevated
access does not bypass Discord's own channel, thread, or role hierarchy checks.

LogiComms is available from the dashboard navigation. Use it according to your community’s communication process, and keep operational messaging clear about audience, timing, and action required.

LogiComms is a Windows download rather than a dashboard messaging control. The
dashboard checks the current release manifest when this page loads and shows a
download button only after it receives a valid HTTPS Windows x86_64 URL. If the
button is unavailable, Logi has not established that a safe current download
is available; wait and retry rather than substituting an unverified link.

<Callout type="warning">
    Elevated access is not a reason to bypass normal checks. Before a
    destructive or broad-impact action, confirm the workspace, the intended
    target, and the user-facing consequences.
</Callout>
